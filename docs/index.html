Multi-AZ Subnet & NAT Routing Architecture

Visualizing high-availability across us-east-2a and us-east-2b

High Availability
💡 Why this setup protects you: Your application servers run completely in the Private Subnets. They do not have public IP addresses, making them immune to direct attacks from the internet. When worker nodes need to download container images or OS security patches, their traffic is safely routed outbound through the NAT Gateway in Public Zone A!

EKS Pod Identity (The Modern AWS Security Model)

Eliminating long-lived AWS keys using the EKS Pod Identity Daemonset

No OIDC Overhead
🚀 Why EKS Pod Identity is superior to older methods: In traditional setups, you had to manage OpenID Connect (OIDC) identity providers and annotate every ServiceAccount with exact ARNs. With AWS EKS Pod Identity (configured in 13-pod-Identity-addon.tf), AWS provides a native node agent that dispenses temporary credentials with zero OIDC federation overhead!

Every File Explained for Beginners

Organized in the exact execution sequence that Terraform uses to provision your cloud infrastructure.

1

Phase 1: Foundation & Variables

Global configurations, cloud provider plugins, and environment constants

0-locals.tf Global Constants

Cluster Settings & Region Definitions

Defines the foundational names and regions used throughout all other files: environment (staging), AWS region (us-east-2), availability zones (us-east-2a, us-east-2b), cluster name (demo), and Kubernetes version (1.31).

locals {
  env = "staging"
  region = "us-east-2"
  eks_name = "demo"
  eks_version = "1.31"
}
1-providers.tf Terraform Plugins

Cloud Providers & Profile Registration

Declares which API plugins Terraform must download (AWS, Helm, Kubernetes, TLS) and instructs the AWS provider to use your configured AWS CLI profile: profile = "my-profile".

provider "aws" {
  region = local.region
  profile = "my-profile"
}
2

Phase 2: High-Availability Cloud Networking (VPC)

Creating the private, isolated data center inside Amazon Web Services

2-vpc.tf & 3-igw.tf VPC & Gateway

Isolated Network & Internet Door

Creates the Virtual Private Cloud (10.0.0.0/16) providing over 65,000 private IP addresses. The Internet Gateway (aws_internet_gateway) serves as the border router allowing internet traffic to enter the public subnets.

Beginner Analogy: The VPC is a secure gated community, and the Internet Gateway is the security gatehouse at the entrance.
4-subnets.tf Multi-AZ Subnets

Public & Private Partitions

Divides the VPC into 4 subnets across 2 physical data centers (Zones A & B). Tagged with special Kubernetes labels so EKS automatically knows where to place public load balancers (role/elb) vs internal load balancers (role/internal-elb).

Key Benefit: If Amazon's Zone A suffers a physical power outage, Zone B continues running with zero downtime!
5-nat.tf & 6-routes.tf NAT & Route Tables

One-Way Outbound Egress

Deploys a NAT Gateway with an Elastic IP in the public subnet. Route tables ensure private worker nodes can reach GitHub, Docker Hub, and AWS APIs outbound, while blocking hackers from initiating inbound connections.

Beginner Analogy: Like a one-way security turnstile—servers can exit to fetch files, but outsiders cannot walk back in.
3

Phase 3: EKS Control Plane & Worker Nodes

Deploying the master brains and the EC2 compute fleet

7-eks.tf Control Plane

Managed Kubernetes Master

Provisions AWS EKS v1.31 control plane running etcd and the Kubernetes API server. Enables modern authentication_mode = "API", which switches from the legacy aws-auth configmap to native EKS Access Entries.

Reliability: AWS manages master high availability, auto-scaling, backups, and security patching 24/7.
8-nodes.tf Managed Node Group

EC2 Worker Compute Fleet

Spins up t3.large EC2 instances in private subnets. Attached with IAM policies for CNI networking, container registry pulling (ECR), and worker node operations. Configured with ignore_changes = [scaling_config[0].desired_size] so the Cluster Autoscaler can scale nodes freely without Terraform conflicts!

Capacity: Min 0, Desired 1, Max 10 nodes on demand.
11-helm-provider.tf Terraform Bridge

Dynamic Auth Bridge

Fetches live cluster endpoints, CA root certificates, and authentication tokens directly from the newly created EKS cluster, allowing Terraform's Helm and Kubernetes providers to install addons automatically.

Zero Manual Steps: Everything from AWS infrastructure to Helm charts installs in one command!
4

Phase 4: Identity, Access Management & RBAC

Zero-trust permissions, temporary role assumption, and developer access

9-add-developer-user.tf

Read-Only Developer Access

Creates an IAM user staging-demo-developer with permissions only to list/describe clusters, mapped to Kubernetes group my-viewer.

Least Privilege
10-add-manager-role.tf

Admin Role Assumption

Implements AWS best practice: user manager cannot access the cluster directly; they must assume role eks-admin with temporary STS tokens.

Temporary STS Creds
13-pod-Identity-addon.tf

EKS Pod Identity Agent

Installs the official eks-pod-identity-agent daemonset on every node to directly issue temporary AWS IAM roles to specific Kubernetes pods.

Modern IRSA Alternative
19-openid-connect-provider.tf

IAM OIDC Federation

Creates an IAM OpenID Connect provider from the EKS issuer URL, enabling legacy web-identity token exchange for tools that rely on OIDC tokens (like EFS CSI and Secrets Store).

Federated Trust
5

Phase 5: Autoscaling, Ingress & TLS Certificates

High-performance traffic management and automated capacity scaling

12-metrics-server.tf

Resource Telemetry

Deploys Kubernetes Metrics Server v3.12.2. Collects CPU and memory usage from kubelets every 15 seconds, powering kubectl top and Horizontal Pod Autoscaling (HPA).

14-cluster-autoscaler.tf

Cluster Autoscaler

Automatically scales EC2 worker nodes up when pods are stuck in Pending status, and shrinks nodes when machines are idle to save cloud costs. Uses Pod Identity for AWS API authorization.

15-aws-lbc.tf

AWS Load Balancer Controller

The bridge between Kubernetes and AWS networking. Reads Ingress/Service manifests and creates real AWS Application Load Balancers (ALB) and Network Load Balancers (NLB) in your VPC.

16-nginx & 17-cert-mgr

Ingress + Automated SSL

Ingress-NGINX receives requests from an internet-facing NLB in IP mode. Jetstack cert-manager automatically provisions and auto-renews free Let's Encrypt TLS/SSL certificates!

6

Phase 6: Enterprise Storage & Secrets Management

Preserving stateful database data and securely mounting production API keys

18-ebs-csi-driver.tf

EBS CSI Driver (Block Storage)

EKS Addon enabling pods to dynamically create, attach, and mount encrypted Amazon EBS SSD disks. Includes KMS encryption rights so sensitive database tables on disk are encrypted at rest.

Mode: ReadWriteOnce (RWO)
Ideal for: Postgres, MongoDB, Redis
20-efs.tf

EFS File System (Shared Storage)

Provisions an AWS Elastic File System (EFS) with mount targets in both availability zones, creates NFS security groups (port 2049), and installs the EFS CSI Helm driver with a custom efs StorageClass.

Mode: ReadWriteMany (RWX)
Ideal for: CMS media, logs, multi-replica apps
21-secrets-store-csi-driver.tf

Secrets Store CSI + AWS Provider

Mounts credentials stored in AWS Secrets Manager directly into pod filesystems as virtual files or syncs them to native Kubernetes Secrets (syncSecret.enabled = true) without writing plaintext passwords in git!

Security: 0 Hardcoded Passwords
Auto-rotates secrets from AWS Secrets Manager

Beginner Operator Cheatsheet

Commands to verify, inspect, and connect to your deployed cluster

Bash / PowerShell
1. Connect your local kubectl to the EKS cluster:
aws eks update-kubeconfig --region us-east-2 --name staging-demo --profile my-profile
2. Verify all worker nodes are Ready:
kubectl get nodes -o wide
3. Check all running system pods & addons:
kubectl get pods -A
4. Get the Public URL of your NGINX Load Balancer:
kubectl get svc -n ingress external-ingress-nginx-controller
